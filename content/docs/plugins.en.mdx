## How it works

The server starts a JVM through JNI inside the `chunkwake` process. The official `paper-api.jar` is on the classpath together with our behaviour implementation, `api-impl`. A plugin sees `Bukkit.getServer()`, `JavaPlugin`, events and schedulers exactly as it does on Paper.

If an event has no listeners, Rust never sends it to the JVM, so unused events cost almost nothing.

## plugin.yml

```yaml
name: HelloPlugin
version: 1.0.0
main: dev.chunkwake.hello.HelloPlugin
api-version: "26.3"
```

Both `plugin.yml` and `paper-plugin.yml` are supported, including Maven `libraries:`, `loader` and `bootstrapper`. If both files are present, `paper-plugin.yml` wins. Libraries are resolved before the main class is created and cached in `libraries/` next to the server. Commands registered through the lifecycle event land in the shared `CommandMap`, which is how `/bluemap` works.

Bukkit/Paper event order is preserved, including cancellation and data replacement. An event that fires after a mechanic on Paper fires after it here too.

## Folia schedulers

Every plugin gets:

- `GlobalRegionScheduler`;
- `RegionScheduler`;
- `AsyncScheduler`;
- `EntityScheduler`.

Ordinary plugins are not disabled as they are on Folia. Plugins with `folia-supported: true` additionally get the region model.

## Data and registries

`PersistentDataContainer` (typed NBT as JSON through `custom_data`), `Metadatable`, registries, tags, attributes and plugin channels are available. Vanilla `net.minecraft.*` classes are on the classpath for plugins that need NMS.

> **Compatibility boundary.** Plugins that reach into CraftBukkit, Netty or `ServerLevel` internals may not work in full. Replicating a Java server without a Java server is not possible, and this is not promised.

What has already been verified on a live server, with versions and limits, is on the [plugin compatibility page](/en/compatibility).

## NMS and CraftEngine

Plugins that need vanilla classes get a generated `net.minecraft.*` layer: registries, block states, packets, `CraftWorld`, `CraftPlayer`, registry events. It is not a complete copy of a Java server, only the classes and methods that live plugins actually reached for.

That is enough for NMS plugins and part of CraftEngine. CraftEngine 26.9.2 starts on a clean API bundle, but its content packs still fail on missing NMS stubs (`MultiPackResourceManager`, `Item#useOn`, `CraftWorld#getUID`). ProtocolLib still does not load: it needs `network.EnumProtocol`, not individual stubs.

## Plugin gate

Compatibility is tested on a live gate: dozens of jars are put into `plugins/`, the server starts, then a bot runs the plugin commands. The last full run of the extended set was **78 of 81**; an earlier revision reached 83/83, but the full gate has not been rerun after the latest changes.

- **MiniMOTD** disables itself: its version gate treats the server as Spigot.
- **VoxyServerSide** disables itself through `plugin.yml` (it requires MC below 26.2).
- **LevelledMobs** does not enable.
- **CraftEngine** reported `LOADERR` in that run; it starts on a clean API bundle, but content packs do not work.

Verified versions and exact limits are on the [compatibility page](/en/compatibility) and in the [feature matrix](/en/docs/feature-matrix).

## Debugging

- `chunkwake doctor --dir ./server` checks Java and configuration.
- `/plugins` shows what enabled, `/mspt` prints average, minimum and maximum MSPT over 5 s, 10 s and 1 min.
- JVM and bridge logs go to the server log.
- An unimplemented method does not kill `onEnable`: it returns an empty value of the right type and logs `api: <interface>.<method>` once. Those lines are the list of gaps.
- `CHUNKWAKE_API_STRICT=1` enables strict mode: an exception is thrown instead of a soft value. It is meant for tests, not normal runs.
- `java/test-plugin` in the repository is a live plugin for events and schedulers.
- Implementation sources: [`java/api-impl`](https://github.com/chunkwake/core/tree/ver/26.3/java/api-impl) and [`crates/bridge`](https://github.com/chunkwake/core/tree/ver/26.3/crates/bridge).
